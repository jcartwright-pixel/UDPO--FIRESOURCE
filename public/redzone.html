1. RedZone API sign-in -

Type these here only, never in a chat or email. Once saved they are locked away and never shown again; only the last 4 characters show. A box left blank keeps what is saved.

2. Test connection

Signs in to RedZone with what is saved and reads the product list. Nothing is ever changed in RedZone.

3. What RedZone gives us

Asks RedZone for every kind of thing it may hold: lines and areas, machines, sensors and data points, data sheets, products, runs, downtime, shifts and sites. RedZone keeps them by site, so it finds our sites first. Each row says how many came back, what each one has and a few examples. Nothing is ever changed in RedZone.

4. Where these come from

  1. Your everyday RedZone user name and password do not go here. RedZone's API uses a client ID and secret, made by a RedZone login with admin rights.
  2. In RedZone, Manage Access > Roles > Create Role: name it "Operations App Read Only" and turn on only Basic Access. Everything else stays off: Admin and every "Configure" or manage switch.
  3. Organization drop-down > Organization Settings > Client Applications > Create Application: name it "Operations App" and pick that role. RedZone shows the Client ID and Client Secret.
  4. Type the client ID and client secret in box 1 and press Save. The API and token addresses are already filled in (RedZone's api.rz-ops.com). The app gets and renews its own tokens; you never handle one.
  5. Press Test Connection. Green means it works; red says what to fix. RedZone's integrations team: integrations@rzsoftware.com.
